Layered Express feature split across controllers → services → repositories, with a dedicated LLM adapter.
- Routes (`routes/ai.routes.js`) mount under `/conversations` with `requireAuth`, `validate` (Zod schemas from `validations/ai.validation.js`), and an `aiLimiter` rate limiter on the message endpoint.
- Controllers (`controllers/ai.controller.js`, `controllers/summary.controller.js`) are thin: they delegate to services via `asyncHandler` and return responses through `sendOk`/`sendCreated`.
- Services implement business logic: `ai.service.js` owns conversation CRUD, ownership checks (`getOwnedConversation` returns 404 for non-owners), resource attachment loading with server membership verification, history truncation (`HISTORY_LIMIT = 20`), and the prompt assembly that prepends a `SYSTEM_PROMPT` plus attached document excerpts before calling the LLM; `summary.service.js` builds a transcript of up to 50 messages and asks Groq for a structured JSON summary parsed via `parseSummaryJson`.
- `services/groq.service.js` is the isolated LLM adapter: it calls `https://api.groq.com/openai/v1/chat/completions` with a bearer token read from `env.GROQ_API_KEY`, enforces a 30s timeout via `AbortController`, maps HTTP status codes to `ApiError` instances, and caps completions at 2048 tokens.
- `repositories/aiConversation.repository.js` wraps Mongoose models `AiConversation` and `AiMessage`; delete cascades by removing all child messages.
- Dependency direction is strictly one-way: routes → controllers → services → repositories + groq.service; no cross-imports between ai and summary services except the shared `groq.service`.
