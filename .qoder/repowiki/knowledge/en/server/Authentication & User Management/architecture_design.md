Follows a layered controller → service → repository pattern over Mongoose models. `routes/auth.routes.js` and `routes/user.routes.js` declare Express routers that compose middleware (`validate`, `requireAuth`, `authLimiter`, `uploadAvatar`) before dispatching to thin controllers in `controllers/`. Controllers only parse request data, call the corresponding service, and format responses via `utils/response.js` and `utils/token.util.js` helpers for cookie setting. Business logic lives in `services/auth.service.js` (register/login/admin-login/email verification/Google OAuth/refresh/logout) and `services/user.service.js` (profile update, avatar upload, password change, public profile lookup); services coordinate domain rules such as allowed email domains, token rotation with family revocation on reuse, constant-time hash comparison, and throttling of verification resends. Data access is isolated in `repositories/`: `user.repository.js` wraps `User` model queries (including selective password projection), while `refreshToken.repository.js` and `verificationToken.repository.js` manage refresh-token lifecycle (create/find/revoke-by-id/family/user-wide/delete) and single-use verification codes respectively. Dependencies flow strictly downward: routes → controllers → services → repositories → models; cross-cutting concerns (validation schemas, error types, logging, storage) are imported from shared `utils/` and `config/` modules.
