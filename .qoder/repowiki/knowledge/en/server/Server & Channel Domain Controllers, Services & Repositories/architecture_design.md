Three-layer MVC-style layout under `server/src` for each domain:
- Routes (`routes/server.routes.js`, `routes/channel.routes.js`) declare Express routers mounted at `/api/v1/servers` and `/api/v1/channels`. They compose middleware in a fixed order: `requireAuth` → path-param validation via `validate()` → ownership/permission checks from `middleware/serverAuth.js` and `middleware/channelAuth.js` (using `PERMISSIONS` bitfields) → controller.
- Controllers (`controllers/server.controller.js`, `controllers/channel.controller.js`) are thin async wrappers around services; they read `req.user`, `req.server`, `req.channel`, `req.membership` populated by earlier middleware and return responses via `utils/response.js` (`sendOk`, `sendCreated`).
- Services (`services/server.service.js`, `services/channel.service.js`, `services/member.service.js`, `services/role.service.js`) hold all business rules: transactional multi-step mutations via `withTransaction`, cross-entity consistency (e.g. creating a default `#general` text channel and `@everyone` role on server creation), permission gating through `resolveMemberPermissions`/`canAccessChannel`, and side effects like emitting socket events (`emitToUsers`) or uploading icons via `storage.util`.
- Repositories (`repositories/server.repository.js`, `channel.repository.js`, `role.repository.js`, `serverMember.repository.js`) are pure Mongoose data access modules exposing `create/updateById/deleteById` plus domain queries; they never import controllers or middleware.
Dependency direction is strictly one-way: routes → controllers → services → repositories → models. Cross-cutting concerns (validation schemas in `validations/*.js`, permissions constants, channel type constants) are imported as shared references rather than duplicated.
