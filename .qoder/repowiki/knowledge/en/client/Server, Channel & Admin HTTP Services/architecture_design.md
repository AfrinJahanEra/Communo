Three thin service modules (`serverService.js`, `channelService.js`, `adminService.js`) each import a single shared `api` client from `../lib/api` and expose named async functions that map one-to-one to backend routes. Each function follows an identical pattern: call `api.get/post/patch/delete`, destructure `{ data }` from the response, and return either the full `data` object or a specific nested field (e.g. `data.server`, `data.channel`, `data.role`). Resources are organized by scope — server-scoped operations live under `/servers/{id}/...`, channel-scoped operations under `/channels/{id}/...`, and platform-wide admin queries under `/admin/...`. File uploads (server icon) use `FormData` with an explicit `multipart/form-data` header override. There is no internal state; these services are pure HTTP wrappers consumed by UI components or higher-level store logic.
