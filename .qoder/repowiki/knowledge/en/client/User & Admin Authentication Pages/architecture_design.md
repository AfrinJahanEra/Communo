The module is split into two layers: a thin `services/authService.js` that wraps HTTP calls to `/auth/*` endpoints via the shared `api` client (and persists tokens through `setAccessToken`), and a set of React page components under `pages/` that compose UI from shared `components/ui`, `components/Logo`, `components/GoogleButton`, and route between screens using `react-router-dom`. User flows are linear state machines driven by router state: Register → CheckEmail → VerifyEmail (with resend cooldowns) → /app; Login handles unverified accounts by surfacing a resend flow. Admin flows are separate: `AdminLogin.jsx` authenticates via `/auth/admin-login` using email + secret key and flips the session in-place through `useAuth().loginAsAdmin`, then renders `AdminPage.jsx`, which uses a local `useAdminQuery` hook to fetch overview/users/servers data from `../services/adminService` and presents them in a sidebar-navigated dashboard. All error messages go through `apiMessage` and all toast notifications through `useToast`; form validation mirrors backend zod rules on the client before sending requests.
